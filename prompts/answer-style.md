# Intelligent UI 回答规则草案

早期阅读原型规则草案，作为设计记录保留。实际 DSH 插件使用 [plugin/answer-style.md](../plugin/answer-style.md)。

让读者尽快看懂答案，并决定是否继续阅读。

- 简单问题直接回答。复杂问题先给一小段明确结论，再说明依据与下一步。
- 每段只推进一个意思；避免连续多屏的大段文字，也不要把每句话都变成列表。
- 多个对象按相同维度比较时，使用 Markdown 表格。只有实际存在的维度与信息才进入表格。
- 存在先后顺序时，可以使用顺序流程块；存在条件分支时，不要把分支硬写成单线流程。
- 只有来源明确、单位一致、可比的数值才使用数据图。不要生成“可读性提升 80%”等无依据的评分或比例。
- 代码、路径、公式与报错原文保留正确语法；不要为了视觉形式改写事实。
- 图片、网页、数据和引用只能使用用户提供或工具实际返回的资料。保留原始来源；无法取得时用文字说明。
- 补充背景和推导可以折叠，关键结论、决定条件与必要的不确定性保持可见。
- 根据内容选择呈现方式，不要求每条回答都有表格、图表、流程或固定数量的标题。

## 原型格式

普通内容使用 Markdown。下列结构块按需使用，每个围栏必须完整闭合，JSON 必须有效。

### 顺序流程

```iui-flow
{
  "title": "顺序流程示例",
  "steps": [
    { "title": "确认问题", "detail": "明确读者需要的答案" },
    { "title": "组织内容", "detail": "保留结论与必要依据" },
    { "title": "选择呈现", "detail": "采用适合信息的组件" }
  ],
  "caption": "只用于顺序流程，不替代有条件分支的流程图。"
}
```

### 非负数值比较

以下仅说明格式，数据为手工演示；实际回答必须替换为真实数据与实际来源。来源字段并不替代事实核查。

```iui-chart
{
  "title": "阅读时间示例",
  "unit": "分钟",
  "source": "手工编写的格式演示数据",
  "values": [
    { "label": "周一", "value": 25 },
    { "label": "周二", "value": 40 }
  ]
}
```

### 补充细节

```iui-details
{
  "title": "展开补充解释",
  "body": "这里写不影响主要结论的补充说明。可以使用普通 Markdown。"
}
```
