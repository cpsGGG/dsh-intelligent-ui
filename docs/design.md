# 阅读设计

> 早期独立阅读原型的设计记录。当前原生 DSH 插件的使用与集成以根目录 README 和 [集成说明](dsh-integration.md)为准。

产品任务：读者不必自己从长文里找重点、拼比较关系、追踪步骤。一个内容入口，按需要选择原文或阅读视图。

## 方向与取舍

采用安静的内容工作台。左侧只负责切换示例与输入；中央是主要阅读区；空间足够时，右侧显示目录。第一屏直接展示实际回答，而不是宣传页、仪表盘或无依据的效果指标。

UI/UX Pro Max 查询 `AI reading assistant content minimal --design-system` 匹配到 AI/Chatbot Platform 与 Minimalism & Swiss Style。采用其中的低界面干扰、清楚层级与交互反馈；通用的紫色配色和营销落地页结构不适合本项目，改为与阅读任务一致的白底、灰色辅助界面、绿色结论强调。

## 视觉约定

- 白色正文 `#ffffff`；浅灰侧栏 `#f7f8f9`；深灰正文 `#242a2d`；辅助文字 `#5f686e`；绿色重点 `#0b7965`；边线 `#e5e9e8`。
- 拉丁文字用本机 Segoe UI，中文用 Microsoft YaHei UI / Microsoft YaHei；不依赖外部字体下载。
- 正文 16px，舒适字号 19px；行高约 1.95。阅读列限制宽度，辅助说明降低视觉权重。
- 只在有实际顺序的流程里编号。表格负责比较，图表负责数值，折叠区负责补充解释。
- 只保留必要的浅色底与边线，减少阅读区外围装饰。

布局：

```text
示例与输入 | 顶部导航
           | 产品说明
           | 原文 / 阅读 / 对比
           | 用户问题
           | 回答主体                章节目录
           | 原文复制与能力说明
```

窄屏改为单列；表格只在内部横向滚动；流程变为纵向；目录收起；对比模式将原文放在阅读内容上方。

## 交互约定

模式按钮暴露 `aria-pressed`；输入有可见标签与错误信息；原文可复制；图表附带无障碍描述与数据表。所有交互支持键盘与可见焦点。减少动态效果偏好下不启用平滑滚动。图片在用户明确点击后才访问原始图片服务器，并保留地址与加载失败提示。

## 内容原则

数据与来源声明必须可见。来源声明仍需要工具核对，不以“存在一个 source 字段”冒充证据验证。无数值不画数据图，无真实图片链接不补图片。普通长文只做保守分段；语义重组留给后续模型接入。
